**Прототип автоматической проверки понятности условий труда в вакансиях Калининградской области.**

Проект получает вакансии с открытого API портала «Работа в России» (регион 39), проверяет полноту и понятность описания и сохраняет замечания в JSON. Анализ сочетает программные правила и локальную языковую модель Ollama.

## 1. Что делает проект

- Загружает вакансии региона 39 через API «Работа в России».
- Обрабатывает несколько страниц API и ограничивает количество записей за запуск.
- Удаляет повторы по идентификатору вакансии.
- Принимает локальные JSON-файлы в формате ответа API.
- Проверяет семь аспектов вакансии: должность, обязанности, требования, оплату, график, место работы и тип занятости.
- Ищет пропуски, неоднозначные формулировки и возможные противоречия.
- Использует локальную языковую модель для дополнительного анализа текста.
- Сохраняет результат в JSON.
- Поддерживает ручной запуск, запуск по локальному расписанию и автоматизацию через GitHub Actions.

Цель проекта — помочь редактору подготовить конкретные уточняющие вопросы работодателю. Сервис не устанавливает факт нарушения законодательства и не заменяет редакторскую или экспертную проверку.

## 2. Технологии и использование ИИ

| Технология | Назначение |
|---|---|
| Python 3.10+ | Основной язык |
| Ollama | Локальный запуск языковой модели |
| Qwen 2.5 3B (`qwen2.5:3b`) | Дополнительный анализ вакансий |
| `python-dotenv` | Чтение настроек из `.env` |
| APScheduler | Локальный запуск по расписанию |
| GitHub Actions | Автоматический запуск базовой проверки |

**Провайдер ИИ:** локальный сервер Ollama.  
**Модель по умолчанию:** `qwen2.5:3b`.  
**API-ключ или платный аккаунт:** не требуются.

ИИ вызывается в `analyzer.py`, в функции `llm_review()`. На этом этапе модели передаются исходные данные вакансии, нормализованные поля и замечания, уже найденные правилами. Модель ищет дополнительные неоднозначности и противоречия и предлагает уточнения.

Ответ модели разбирается как JSON. Замечания с неполными обязательными полями отбрасываются; непустая цитата принимается только тогда, когда она встречается в исходных данных вакансии. Результаты ИИ объединяются с результатами правил, повторяющиеся замечания исключаются.

Если Ollama недоступна или возвращает некорректный ответ, программа выводит предупреждение и продолжает работу с базовыми правилами. Поэтому для демонстрации именно ИИ-анализа необходимо заранее запустить Ollama и загрузить модель.

Все команды ниже выполняются из корневой папки проекта.

```bash
git clone ССЫЛКА_НА_РЕПОЗИТОРИЙ
cd prozrachnaya_vakansiya
```

Замените `ССЫЛКА_НА_РЕПОЗИТОРИЙ` на адрес публичного репозитория команды.

Если проект уже скачан архивом, распакуйте его и откройте папку `prozrachnaya_vakansiya` в терминале или VS Code.

### Шаг 2. Создать виртуальное окружение

```bash
python -m venv .venv
```

**Windows PowerShell:**

```powershell
.venv\Scripts\Activate.ps1
```

Если PowerShell запрещает запуск скрипта активации, можно использовать командную строку Windows:

```bat

```

**Linux/macOS:**

```bash
source .venv/bin/activate
```

```bash
python -m pip install --upgrade pip

```

### Шаг 4. Настроить Ollama

1. Установите Ollama с официального сайта: <https://ollama.com/>.
2. Загрузите модель:

```bash
ollama pull qwen2.5:3b
```

3. Убедитесь, что модель появилась в списке:

```bash
ollama list
```

Приложение Ollama обычно само запускает локальный сервер. Если сервер не запущен, выполните:

```bash
ollama serve
```

Ожидаемый адрес локального сервера по умолчанию: `http://localhost:11434`.

### Шаг 5. Создать файл настроек

Скопируйте пример `.env.example` в `.env`.

**Windows PowerShell:**


**Linux/macOS:**

```bash

```

При необходимости отредактируйте `.env`. Файл `.env` исключён из Git и не должен публиковаться в репозитории.

## 6. Настройки

| Переменная | Назначение | Значение по умолчанию |
|---|---|---|
| `SOURCE_URL` | Адрес API региона | `http://opendata.trudvsem.ru/api/v1/vacancies/region/39` |
| `MAX_VACANCIES` | Максимум вакансий за один запуск | `200` |
| `REPORT_PATH` | Путь к рабочему отчёту | `reports/latest.json` |
| `OLLAMA_URL` | Адрес локального сервера Ollama | `http://localhost:11434` |
| `OLLAMA_MODEL` | Имя модели Ollama | `qwen2.5:3b` |
| `OLLAMA_TIMEOUT` | Тайм-аут запроса к модели, секунд | `90` |
| `SCHEDULE_HOURS` | Интервал запуска планировщика, часов | `24` |
| `TIMEZONE` | Часовой пояс планировщика | `Europe/Kaliningrad` |

Размер страницы API задаётся аргументом `--page-size`; допустимое значение — от 1 до 100.

## 7. Режимы работы

### 7.1. Проверочный режим — локальный JSON

Режим предназначен для демонстрации и тестирования без обращения к порталу.

**Проверка с ИИ:**

```bash
python main.py file sample_data/example_api.json --output reports/check.json
```

Для этого варианта должны быть запущены Ollama и модель `qwen2.5:3b`.

**Проверка только программными правилами:**

```bash
python main.py file sample_data/example_api.json --no-ai --output reports/check.json
```

Входной файл должен содержать JSON в формате ответа API «Работа в России». В репозитории находится учебный пример `sample_data/example_api.json`.

### 7.2. Рабочий режим — получение вакансий через API

Источник данных — открытый API вакансий Калининградской области:

<http://opendata.trudvsem.ru/api/v1/vacancies/region/39>

Запуск с ИИ:

```bash
python main.py api
```

Запуск без ИИ:

```bash
python main.py api --no-ai
```

Пример с изменённым лимитом и путём отчёта:

```bash
python main.py api --max-vacancies 250 --page-size 100 --output reports/latest.json
```

Программа загружает страницы API, обрабатывает вакансии, удаляет дубликаты по ID и сохраняет отчёт. Параметры `offset` и `limit` используются для постраничного получения данных; размер страницы не превышает 100 записей.

Если API недоступен или возвращает ошибку, программа сообщает об этом и не перезаписывает существующий успешный отчёт.

### 7.3. Автоматический запуск по расписанию

```bash
python main.py serve
```

Планировщик выполняет первую обработку сразу после запуска, затем повторяет её через интервал `SCHEDULE_HOURS` (по умолчанию 24 часа). Часовой пояс задаётся переменной `TIMEZONE`.

Для работы ИИ в этом режиме Ollama должна оставаться запущенной. Чтобы остановить планировщик, завершите процесс в терминале сочетанием `Ctrl+C`.

## 8. Как работает анализ

### Этап 1. Получение и нормализация данных

`main.py` загружает вакансии из API или читает локальный JSON. Модуль `analyzer.py` извлекает поля вакансии и приводит вложенные значения, например адреса и сведения об оплате, к текстовому виду.

### Этап 2. Проверка программными правилами

Проверяются семь направлений:

1. Название должности.
2. Обязанности.
3. Требования.
4. Оплата труда.
5. График работы.
6. Место работы.
7. Тип занятости.

Правила выявляют отсутствующие структурированные значения и некоторые очевидные неоднозначности, например формулировку «гибкий график» без конкретных дней и часов. Для отдельных полей также учитываются явно подписанные сведения в текстовом описании.

### Этап 3. Дополнительный анализ ИИ

Функция `llm_review()` отправляет данные локальной модели через HTTP API Ollama. Модель получает инструкцию не придумывать сведения, не делать юридических выводов и не повторять уже найденные замечания.

ИИ может обнаружить дополнительные неоднозначности или противоречия между частями описания. Его ответ проверяется и объединяется с результатами правил.

### Этап 4. Формирование отчёта

`main.py` удаляет повторяющиеся записи по ID вакансии и атомарно сохраняет JSON-отчёт. Атомарная запись позволяет не оставлять частично сформированный файл при сбое записи.

## 9. Формат итогового отчёта

Отчёт содержит дату формирования, регион, количество обработанных вакансий и массив результатов.

Пример:

```json
{
  "generated_at": "2026-11-24T12:00:00+00:00",
  "region": "39",
  "vacancies_count": 1,
  "vacancies": [
    {
      "id": "12345",
      "url": "https://example.com/vacancy/12345",
      "issues": [
        {
          "topic": "График",
          "source_field": "schedule / description",
          "quote": "гибкий график",
          "problem": "Не указаны конкретные дни и часы работы.",
          "recommendation": "Уточните рабочие дни и время начала и окончания смены."
        }
      ]
    }
  ]
}
```

Поля отчёта:

| Поле | Значение |
|---|---|
| `generated_at` | Дата и время формирования отчёта в ISO 8601 |
| `region` | Код региона, для проекта — `39` |
| `vacancies_count` | Число вакансий в отчёте |
| `vacancies` | Массив обработанных вакансий |
| `id` | Идентификатор вакансии |
| `url` | Ссылка на карточку, если она присутствует в источнике |
| `issues` | Массив замечаний; если проблем нет — `[]` |

Каждое замечание содержит:

- `topic` — тема проблемы;
- `source_field` — поле или часть исходных данных;
- `quote` — цитата или значение из источника; для пропуска — пустая строка;
- `problem` — описание того, что мешает понять условия;
- `recommendation` — конкретное уточнение для работодателя.

Для противоречия в цитате следует приводить оба исходных значения. Если замечаний не обнаружено, массив `issues` остаётся пустым.

## 10. Тестирование

Запуск всех автоматических тестов:

```bash
python -m unittest -v
```

Тесты проверяют:

- чтение ответа API и извлечение вакансий;
- формирование отчёта;
- пустую цитату для отсутствующего поля;
- объединение диапазона оплаты и валюты;
- извлечение адреса из вложенного массива;
- обнаружение неоднозначного графика в описании;
- сохранение разных вакансий без ID как отдельных записей;
- переход к следующей странице API;
- ограничение размера страницы API.

Для быстрой ручной проверки:

```bash
python main.py file sample_data/example_api.json --no-ai --output reports/check.json
```

После запуска откройте `reports/check.json`. В учебном примере первая вакансия должна содержать замечание о неопределённом графике, а вторая — пустой массив `issues`.

## 11. Автоматизация через GitHub Actions

Файл автоматизации: `.github/workflows/daily.yml`.

Workflow поддерживает:

- ручной запуск через вкладку **Actions** в GitHub;
- ежедневный запуск по расписанию;
- сохранение JSON-отчёта как артефакта выполнения workflow.

Текущий workflow запускает команду:

```bash
python main.py api --no-ai
```

То есть GitHub Actions выполняет базовые проверки без локальной модели Ollama. Это сделано потому, что локальная Ollama не установлена на стандартном GitHub-hosted runner.

Для автоматического ИИ-анализа используйте локальный планировщик `python main.py serve` на компьютере или сервере, где установлена и запущена Ollama.

## 12. Ограничения

- Результат зависит от полноты и структуры данных, предоставляемых API.
- Структура отдельных полей API может меняться; при появлении новых вариантов потребуется расширить нормализацию.
- Программные правила выявляют только заранее предусмотренные случаи.
- Ответ языковой модели может быть неполным или ошибочным. Перед использованием замечаний необходима редакторская проверка.
- При недоступности Ollama выполняются только базовые проверки.
- Проект не устанавливает факт нарушения законодательства и не заменяет экспертную оценку условий труда.
